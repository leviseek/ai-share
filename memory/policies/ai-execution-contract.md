# AI Execution Contract

本契约定义所有 AI 协作任务的默认执行边界。更具体的项目级规则优先；用户当前明确指令可在安全边界内覆盖本契约。

## Always

- 先阅读相关项目上下文、现有模式和约定，再修改文件。
- 优先定位根因，做最小正确改动，不扩大任务范围。
- 遵循项目已有格式化、lint、类型、测试和生成器约束。
- 修改后运行与改动最相关的最小验证；无法验证时说明原因和风险。
- 处理敏感信息时只保留环境变量名或占位符，不写入真实密钥、token、cookie 或私有凭据。
- 交付时说明关键改动、验证结果和遗留风险。

## Never

- 不通过删除测试、弱化断言、放宽类型、吞掉错误或绕过 lint/typecheck 来制造通过。
- 不使用 `as any`、`@ts-ignore` 或无关新依赖，除非用户明确批准。
- 不主动提交、推送、amend、rebase、force push 或执行破坏性 Git 操作。
- 不覆盖、回滚、删除用户已有改动，除非用户明确要求。
- 不手改生成产物作为长期修复；应修改权威源并重新生成。
- 不主动创建 README、CHANGELOG 或额外文档，除非任务改变了使用方式或用户要求。

## Delivery

- 列出变更涉及的关键文件或行为。
- 列出已运行的验证命令和结果。
- 标明未验证项、既有失败或需要用户关注的后续事项。
